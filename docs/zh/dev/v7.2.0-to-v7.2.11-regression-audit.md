## 本次已修复

### 1. 神医 override 原子替换权限退化

`mkstemp()` 创建的临时文件通常只有创建者可读。旧实现直接 `os.replace()`，可能把
原本可由神医容器读取的 `0644/0640` JSON 替换成不同 UID 无法读取的文件。

修复后：

- 已有 override 继承原 override 的权限；新建 override 继承 cache 权限；
- 尽力保留 UID/GID，再重新应用权限位；
- 无法维持来源文件可读身份时失败关闭，不替换目标；
- 保留原有指纹复核、同目录临时文件、双 `fsync` 和原子替换。

### 2. 非幂等 POST 的重定向与不确定结果

修复后：

- 所有非安全 HTTP 方法默认禁止跟随重定向；`post_once()` 明确
  `allow_redirects=False`；
- 2xx 视为已提交；3xx/4xx 视为明确拒绝；
- 5xx、timeout、连接重置、代理/TLS 和响应截断视为交付结果不确定；
- 不确定结果只读确认并进入冷却，不自动重放。

### 3. 元数据刷新账本跨重启丢失

刷新状态原先仅保存在进程内 512 项 LRU 中，重启后会丢失“已经提交、结果不确定、
人工重试已用”等信息。

修复后：

- 复用现有 `app_settings` 保存最多 512 项刷新账本，无数据库迁移；
- 在真正发送 POST 前先持久化 `refresh_pending`；
- 一次人工重试限制和歧义冷却可跨进程重启保留；
- 持久化失败时不发送刷新 POST。

同时修复了一个功能缺口：当 override/数据库本来已经完整、但 Emby 字段仍为空时，
首次执行现在会提交一次最小 Provider 刷新，而不是错误地停在“无来源写入”。

### 4. MoviePilot 同订阅并发重复写入与日志泄露

修复后：

- 按 MoviePilot 地址、TMDb ID 和季号建立引用计数键锁；
- 状态同步在锁内重新读取真实订阅详情，不以调用方传入的旧快照做写入判断；
- 订阅、取消和更新请求禁止跟随重定向；
- 失败日志不再记录 MoviePilot 完整响应正文；
- 锁在无人使用时清理，不形成无限增长字典。

### 5. 实时监控事件线程无上限

即时批次、删除批次和自适应到期批次原先会为每批创建新 daemon thread。事件风暴下
线程数可能失控。

修复后改为共享 `ThreadPoolExecutor(max_workers=4)`，最多 64 个运行/排队槽位；
队列满时施加背压，不静默丢任务，后台异常会统一记录。STRM 有限重试线程和定时
查漏线程仍是各自唯一的长期线程，不属于这项问题。

### 6. 旧分身演员合并删除旁路

旧任务没有复用 v7.2.7 的保护库快照和最终 fail-closed 引用核验。现在已从任务注册表
和导入链移除，公开函数入口也直接抛错。旧实现只保留为不可达代码，迁入统一安全
闭环前不能恢复。

### 7. 发布验证缺口

新增 `.github/workflows/pr-validation.yml`：

- Python 3.12 安装依赖、`compileall`、完整 unittest discovery；
- Node 20 安装前端依赖并执行生产构建；
- 同一 PR 新提交会取消旧验证，避免并行浪费。

该工作流只有推送到 GitHub 后才能形成独立证据；本地生成工作流文件不等于 CI 已通过。

## 仍未解决，不应掩盖

### 高风险：旧追更全量元数据链

`watchlist_processor._save_local_json()` 仍会直接原地改写神医 override，缺少新回填服务的
路径边界、文件锁、并发指纹和原子替换保护。随后旧链还会以
`ReplaceAllMetadata=true` 刷新 Series。注册任务 `refresh_completed_series` 仍可进入
该流程。

处置：v7.2.11 发布前不要运行“全量刷新剧集/已完结剧集复活检查”这条旧重型任务；
在 v7.2.12 将它迁移到统一的安全 merge/刷新契约后再恢复。

### 高风险：旧数据库广域写入口会用空值覆盖已有值

以下旧接口仍不具备 selective-fill 语义：

- `ensure_media_record_exists()` 的冲突更新；
- `update_media_metadata_fields()`；
- `sync_series_children_metadata()`，且仍跳过 Season 0。

它们可能用 `NULL`、空简介、空 JSON、零评分或占位数据覆盖已有元数据。本次新增的
神医安全回填不调用这些旧入口，因此不阻断该新功能审核；但不能据此宣称全仓数据库
写入已经安全。建议 v7.2.12 统一迁移，并对每个旧调用方增加非降级回归测试。

### 中风险：STRM 自适应窗口仍为内存状态

进程重启会丢失当前 75 秒/静默窗口的聚合状态。现有数据库有限重试和定时查漏可恢复
实际未收录路径，但不能恢复原批次节奏。建议后续持久化作品聚合键、首次/最后事件时间
和待处理路径摘要。

### 中风险：路径身份仍不是 realpath/inode 身份

当前聚合和精确匹配主要使用 `normpath/normcase`。软链接、bind mount 别名或大小写规则
不同的文件系统可能使同一实体路径重复入队。后续应在不越过媒体库根边界的前提下建立
规范 realpath 身份，并保留原 Emby 路径用于 API 查询。

### 中风险：前端依赖

ECharts `<6.1.0` 的已知中等级公告需要 ECharts/vue-echarts 跨大版本升级，不能在
v7.2.11 中无验证强升。应单独做图表 API 兼容和输入边界测试。

### 发布卫生

`release_notes.py` 已提前放入 v7.2.11 的发布时间和 Release URL。正式发布前应改成
真实发布时间；在 Release 尚未创建时不要把该时间视为发布证据。
