# EVH v7.2.11 阶段 A 审计与阶段 B 设计

## 审计边界

- 基线：`v7.2.7` (`00677d4b`) 至 `v7.2.10` (`f1e9d102`)。
- 目标：在不绕开神医助手 Pro、不读取或修改 MediaInfo JSON、不重新实现
  ffprobe/dffmpeg 的前提下，为 Emby 已缺失的文本元数据提供安全回填。
- 固定目录：神医元数据根目录与 EVH `local_data_path` 必须指向同一个
  `/STRM/HC`。
- 回归保护：人物删除安全闭环、STRM 精准刷新、MoviePilot 幂等同步。

阶段 A 只进行了源码、Git 历史、现有测试与隔离实验环境的只读取证。阶段 B
开始后才创建 `fix/7.2.11-shenyi-safe-metadata-backfill` 分支。

## 版本核验

### v7.2.7 人物安全

主清理链已经实现保护媒体库快照、实时作品引用复核、分页与详情回退，并在引用
不可核验时 fail closed。遗留风险是 `merge-duplicate-actors` 仍可从另一条任务链
直接删除人物，未复用同一套保护快照和最终引用复核。

### v7.2.8 MoviePilot 幂等

主同步链已改为先读取完整订阅详情、规范化数字字符串、内容未变化不 PUT，更新后
再读取确认。复审发现同一订阅缺少进程内串行锁，两个并发任务仍可能同时完成
GET/比较/PUT；异常与失败响应还可能把完整响应正文写入日志。**v7.2.11 已修复**：
订阅变更按 MoviePilot 地址、TMDb ID 和季号串行化，变更前强制重新读取，失败日志
只记录状态码，所有变更请求禁止跟随重定向。

### v7.2.9 STRM 自适应入库

已实现按剧集/季度聚合、延迟窗口、重试队列和精确路径通知。遗留风险包括：

- 路径收录核验仍请求 `MediaSources`，可能让 Emby/神医重新打开 STRM 源并触发
  媒体信息提取。
- 即时批次与到期批次原先以守护线程启动，缺少有界工作池。**v7.2.11 已修复**：
  改为固定 4 worker、最多 64 个运行/排队槽位的共享执行器，队列满时背压而不丢任务。
- 自适应窗口状态只在内存中，重启后丢失；路径只做 `normpath`，软链接/大小写别名
  可能重复入队。

### v7.2.10 实体库精准刷新

最长根路径匹配、同长度歧义拒绝、实体库浅刷新与 STRM 锚点边界均已实现。遗留风险
是 `refresh_item_by_id` 仍使用允许 POST 重试的共享 Session；响应丢失时可能重复
提交刷新。删除后的失败行只依赖后续盘点自愈，仍可能长期残留。

## 任务书外发现

### 严重

1. `handler/emby.py` 的共享 `Retry` 允许 `POST/PUT/DELETE`。STRM 刷新、
   `DeletePerson` 等非幂等请求存在自动重放风险。**v7.2.11 已修复**：共享重试器
   只允许安全方法，刷新、通知和删除统一走 `post_once`。
2. `is_media_path_indexed` 与 `get_media_item_by_path` 默认请求 `MediaSources`，
   与“神医接管 ffprobe/dffmpeg、EVH 不触发探测”的架构冲突。
   **v7.2.11 已修复**：精准路径核验默认不再请求 `MediaSources`。
3. `merge-duplicate-actors` 是未纳入 v7.2.7 安全闭环的人物删除入口。
   **v7.2.11 已止血**：从任务注册表和导入链移除，公开任务函数本身也直接失败关闭；
   迁入 v7.2.7 安全闭环前不可触发。

### 高

1. `ensure_media_record_exists` 的冲突更新会用 `NULL` 或空值覆盖已有元数据。
2. `sync_series_children_metadata` 和 `update_media_metadata_fields` 允许空简介、
   空 JSON、零评分等覆盖已有数据；特别篇第 0 季还被跳过。
3. 旧 `_save_local_json` 直接覆盖神医 JSON：无路径边界、锁、原子替换、
   mtime/hash 复核，并且会用新值覆盖已有值。
4. 旧追更刷新会解锁 Emby 项目、清空 `LockedFields` 并提交
   `ReplaceAllMetadata=true`，不能复用于安全回填。

### 中

1. **已在 v7.2.11 修复**：MoviePilot 同订阅并发更新增加有界键锁，失败响应正文脱敏。
2. **已在 v7.2.11 修复一半**：STRM 即时任务改为有界执行器；自适应窗口状态仍未持久化。
3. 精确路径仅做字符串规范化，不处理软链接或不同大小写文件系统别名。
4. 前端依赖审计存在 ECharts `<6.1.0` 的中等级 XSS 公告
   `GHSA-fgmj-fm8m-jvvx`；自动修复要求 ECharts 6 与 vue-echarts 8 跨大版本
   升级。该依赖风险并非 v7.2.11 引入，需单独做图表兼容与输入边界验证。

## 神医真实缓存契约

依据神医官方文档，根目录下由神医初始化 `cache` 和 `override`：

- 电影：`tmdb-movies2/<tmdb_id>/all.json`
- 电视节目：`tmdb-tv/<tmdb_id>/series.json`
- 季：`tmdb-tv/<tmdb_id>/season-N.json`
- 集：`tmdb-tv/<tmdb_id>/season-N-episode-N.json`
- 合集：`tmdb-collections/<tmdb_id>/all.json`

`override` 始终优先且由神医只读消费；`cache` 是神医被动缓存。EVH 只允许读取
`cache`，并只允许在已有完整基底时对 `override` 做“缺失字段补齐”。EVH 不读取、
不写入任何 MediaInfo JSON 目录。

## v7.2.11 设计

### 数据优先级

1. Emby 已有值、`LockData` 和 `LockedFields`；
2. 神医 `override` 已有非空值；
3. EVH PostgreSQL 已有非空值；
4. 神医 `cache` 原始 TMDb 值；
5. 本版本不主动在线抓取；无可信来源即跳过。

“空”统一定义为：`None`、空白字符串、空列表、空对象、表示空列表/对象的 JSON
字符串、无意义占位日期，以及仅在对应字段语义下的零值。已有非空值永不被降级。

### 安全写入

- 只接受正整数 TMDb ID 和 `Movie/Series/Season/Episode`。
- 所有解析后的目标路径必须位于规范化 `local_data_path/override` 内。
- 拒绝目录穿越、目标或父目录软链接、越界 realpath。
- 已有 override 文件才允许补齐；如需从 cache 建立 override，必须先读取完整有效
  基底，再复制完整对象并仅补缺。
- 单目标进程锁；锁内重新读取并比较 mtime、大小和 SHA-256。
- 同目录临时文件、继承已有 override（或新建时 cache）的权限并尽力保留属主/属组、
  flush、fsync、`os.replace`，随后 fsync 父目录；无法维持原可读身份时失败关闭。
- 不修改 `id`、季号、集号等结构身份字段；不记录完整路径、JSON 或凭据。

### 数据库

- 新增专用的 selective-fill 更新，只更新当前数据库确实为空且候选非空的允许字段。
- 官方分级与评分分开处理；自定义评分不得写入 `official_rating_json`。
- 结构化字段先经过 source → canonical → target 转换：EVH 数据库的国家分级固定
  为“国家代码 → 分级”对象，国家固定为 ISO 代码数组；Movie 的神医文件保持
  `release_dates` / `production_countries`，Series 保持 `content_ratings` /
  `origin_country` 的真实 TMDb schema，禁止对象和数组原样互写。
- 预览、文件层和 SQL selective-fill 共用同一缺失语义；占位标题、占位日期、
  空 JSON 和零数值在三层的判定一致。
- 不改订阅状态、在库状态、人物、图片、资产详情或 MoviePilot 字段。

### Emby 刷新

- 隔离实测确认 Emby 4.9.5 的 `MetadataRefreshMode=Default` 不会调用被神医
  接管的远程元数据 Provider。专用神医模式因此使用单 item
  `MetadataRefreshMode=FullRefresh`，但仍固定为 `Recursive=false`、
  `ReplaceAllMetadata=false`、`ReplaceAllImages=false` 和
  `ImageRefreshMode=ValidationOnly`；它不调用 EVH 的
  `force_full_update=True` 或任何全库/人物/图片/MediaInfo 链路。
- 不解锁、不清空 `LockedFields`，使用禁止重定向的 `post_once`，同项目去重。
- 仅在 JSON 或数据库确有变化时刷新实际缺失的项目；Season/Episode 不升级为
  Series 递归刷新。
- override 原子替换后提供一次固定 0.5 秒的 Provider 可见性窗口，刷新 POST
  仍只提交一次；随后最多三次只读查询目标字段，不用查询失败触发再次刷新。
- 执行结果显式记录 `source_updated`、`refresh_pending`、`refresh_submitted`、
  `provider_confirmed`、`refresh_failed` 和 `refresh_ambiguous`。提交意图先持久化；
  3xx/4xx 明确拒绝只允许管理员显式重提一次，5xx、超时和连接类异常先只读核验，
  并在冷却结束后才接受人工显式重试，不存在自动循环刷新。

### API 与任务

- 管理员 POST API：dry-run、单项和批量（最多 100 个根项目）。
- GET 只读取任务状态，不启动回填。
- 每项独立结果和失败原因；重试前重新读取全部来源。
- 后台任务复用固定大小为 2 的 executor，不再为每个 POST 建 daemon Thread；
  active key 按根 Series 归一化，不同 Episode 不能绕过去重。文件锁、项目锁和
  future 完成后均清理；刷新账本通过 `app_settings` 持久化并限制为 512 项。
- 回填链不调用人物、图片、MoviePilot、向量、媒体扫描或完整刷新。

## 阶段 B 实施结果

### 实际变更

- 新增独立 `ShenyiMetadataBackfillService`，不依赖在线 TMDb、豆瓣、人物、
  图片、MoviePilot、MediaInfo 或 ffprobe；支持 Movie、Series、Season 0、
  Season、Episode 的 dry-run、单项和最多 100 项批处理。
- `cache` 仅作为只读候选源；新建 override 前按媒体类型检查完整 TMDb 响应
  关键键，并核对 Movie/Series 的 TMDb ID 与 Season/Episode 编号确实匹配缓存
  路径，避免错身份或“只有标题/简介”的残缺对象被神医 Provider 读取后异常。
- 新增结构化字段转换契约，分离 EVH JSONB 与 Movie/Series 的真实神医 schema；
  国家分级、国家代码、类型、公司和电视网均在写入前做结构校验。
- 已有 override 只补空值；目标文件使用每文件锁、mtime/大小/SHA-256 复核、
  来源权限/可读身份继承、同目录临时文件、双 `fsync` 和 `os.replace`，并拒绝
  软链接、绝对路径和 `..` 逃逸。dry-run 不创建目录或文件。
- PostgreSQL 新增独立 allowlist selective-fill：只更新数据库当前仍为空且
  候选非空的列；不做迁移，不写 `custom_rating`、人物、图片、订阅或在库状态。
- 新增管理员 API：`POST /api/metadata-backfill/preview`、
  `POST /api/metadata-backfill/tasks` 和只读
  `GET /api/metadata-backfill/tasks/<task_id>`。
- 刷新失败状态可恢复：提交意图先持久化；文件/数据库写成功后，仅 3xx/4xx 明确拒绝保留一次显式重试入口；
  5xx、timeout、连接中断、代理/TLS 与响应截断均进入歧义状态，先只读确认并冷却；
  307/308 不跟随，任何被动重跑均不会再次 POST。
- Season/Episode 即使自身没有 ProviderIds，也可由 EVH DB 反查根 Series TMDb，
  并从已定位的真实神医 cache `id` 取得子项目身份。
- 任务执行改为有界工作池，根 Series 去重；引用计数锁和完成 future 会及时清理。
- MoviePilot 同订阅变更增加键锁、变更前重新读取、响应正文脱敏和重定向拒绝。
- 实时监控即时/删除/到期批次改为固定 4 worker、64 槽位的有界执行器。
- 共享 HTTP 重试器移除非幂等方法；STRM 精确查询移除 `MediaSources`；
  旧人物合并删除任务从注册表、导入链和函数入口三层禁用。

### 隔离实验栈

- Mac 只运行一个隔离测试 Emby；设备 ID、唯一测试授权文件名和授权内容一致，
  神医助手 Pro 页面与完整设置页可用。
- 神医追更模式开启，任务范围包括媒体信息提取、原生片头探测、行为标记同步和
  剧集元数据刷新；主/次线程分别为 3/4；中文搜索开启并在重启后确认 tokenizer
  为 `simple`。
- 神医元数据根目录和 EVH `local_data_path` 均为容器内 `/STRM/HC`，共同映射
  到同一隔离宿主目录；测试媒体库使用 `/STRM/...`，不复用 NAS 的
  `/volume3/STRM`。
- 正式计划模式设为“优先使用缓存”。测试“电影”库补齐 TheMovieDb provider
  后，神医在线模式先生成真实 Movie 缓存，再切回优先缓存执行验收。
- 使用真实神医 cache/override 对 Movie、Series、Season 0、普通 Season、
  Episode 分别执行 FullRefresh 哨兵 E2E。每项只留一个目标字段为空；Movie、
  Series、Episode 补简介，两个 Season 补首播日期。标题、其余简介/日期、评分、
  类型、分级、工作室、人物、图片标记、`LockedFields` 和 `LockData` 全部保持。
- 最终日志窗口只有上述 5 次单项目刷新；MediaInfo、ffprobe、dffmpeg、人物、
  图片下载和 MoviePilot 的触发计数均为 0。
- MoviePilot 未做站点认证，因此未把站点、Cookie、下载器或 115 纳入端到端；
  v7.2.8 的幂等 GET/比较/PUT、失败不补订和回读确认继续由隔离契约测试覆盖。

## 审计结论

v7.2.7 至 v7.2.10 的主安全边界保持成立。可直接造成删除越权、非幂等重放、
STRM 探测副作用、跨 UID 文件不可读和同订阅重复提交的问题已在 v7.2.11 修复或
停止入口；本版新增回填链与旧重型链完全隔离。仍未解决的是旧追更全量覆写、
全仓广域数据库空值覆盖、自适应窗口持久化和路径真实身份问题，按上述版本延后；
在这些旧入口不被本次安全回填调用的前提下，不阻断 v7.2.11 继续审核。
