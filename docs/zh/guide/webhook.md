# Webhook 接入

Webhook 用于接收 Emby 事件并触发对应处理。

## 配置地址

```
http://<服务器IP>:5257/webhook/emby?token=<Webhook Token>
请求内容类型：application/json
```

`Webhook Token` 在后台「高级」-「安全设置」中配置。也可以不放在 URL 中，改用请求头 `X-Webhook-Token` 携带同样的值。

## 推荐事件

- 媒体：添加、删除
- 播放：开始、停止
- 用户：添加到收藏、移出收藏、标记已播放、标记未播放、用户政策已更新
- 神医助手：元数据更新、图像更新

## 行为说明

- Webhook回流，补全实时监控预处理缺失的Emby_id和视频流数据。
- 用户事件：实时同步用户权限、播放记录。
- 元数据/图像更新：同步更新Emby修改图像、元数据到覆盖缓存和数据库。

## 速率控制

Webhook 内置去抖与批处理逻辑，可减少高频事件对 Emby 的压力。

## 失败记录恢复与归档

“失败”表示该次事件未完成，不一定代表媒体目前仍有故障。媒体恢复正常后，不必为了消除历史告警反复重试。

- **已恢复**：后续媒体处理成功，且来源、精确媒体 ID、任务类型、处理参数一致，Episode ID 集合覆盖旧失败批次。成功执行必须在旧事件失败之后开始。仅凭剧名相同不会自动核销；缺失、未知或不完整证据仍保留为失败。
- **已归档**：管理员已检查媒体、集数、详情及播放正常，通过“确认已恢复并归档”显式确认。它不代表原事件执行成功，不触发 Webhook 重放，不修改媒体或 Person。
- **待处理失败**：尚无覆盖证据、也没有人工确认的失败。需要继续排查时才使用“重试”。处理中和等待重试的事件不能归档。

升级启动时会使用队列中已有成功证据核对旧失败记录，不需要重新处理媒体。恢复／归档保留原错误及关联成功事件或确认人，不再计入待处理失败；沿用原来的 30 天历史保留规则，从恢复／归档时间起计算。未解决的失败不会自动过期。

这里的状态只针对 Webhook 队列，与 STRM 文件监控／删除同步队列独立。
