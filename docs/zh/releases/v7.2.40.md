# v7.2.40 — P0 Person enrichment / Media ingest Hotfix

修复 v7.2.39 的可选 Person 身份拒绝导致正常媒体后处理中断的问题。

- Person gate 的明确拒绝进入持久 HOLD / 待复核，不再等同于媒体入库失败。
- 媒体基本字段及 Series / Season / Episode 缓存同步继续；Webhook 仅在核心媒体处理成功后完成。
- HOLD 时保留原生 Emby People、已有演员/导演缓存，不写空 People、不刷新读取旧演员覆盖文件。
- existing-only / exact identity 不放宽；不自动创建、解绑、删除、合并 Person，不补满 50。
- 真实媒体缺失、数据库/事务错误和未知异常继续失败。已处理内存缓存仅在媒体事务提交后更新，防止失败重试被误跳过。
- 增加姓名冲突、provider 缺失、同名异人、六集层级同步、失败事件重试及重复投递回归。

不修改历史 Person Cleanup、删除资格、Series main-only、Episode guest scope、VidHub、Infuse、虚拟库、Recent、播放、更新器、数据库结构或 UI。
不包含临时审计工具、生产扫描产物或测试数据文件。本次发布未操作 NAS 生产环境，也未重放生产 Webhook。

## 升级和失败事件恢复

正式镜像：`tzyzero186/emby-vision-hub:7.2.40`，`latest` 为同一 GitHub Actions 正式构建。

通过现有 Portainer Stack / Compose 管理器更新，保留现有 mounts、env、ports、network 和 `/config`。不要只 pull 后 restart 旧容器；需确认容器已重建，运行版本为 7.2.40 且 health 为 healthy。

本版本不会自动重放历史失败事件。对事件 1319 等故障：

1. 升级成功后，先在 Webhook 队列核对事件仍是 failed、媒体 ID 正确、六个 Episode ID 完整，且没有同目标 processing 任务。
2. 管理员使用现有队列的“重试”操作一次（`POST /api/tasks/webhook-events/1319/retry`）。不要直接修改数据库或批量重投历史事件。
3. 若已有 pending/retry 后继事件，现有队列会合并 exact Episode IDs，旧事件可能变为 superseded；应核验对应后继事件完成。
4. 核验媒体缓存已同步、事件 completed、Person HOLD 单独保留；再检查原生 Emby 及 EVH 的六集、层级、详情、虚拟库、Recent 和播放。
5. 若 payload 不完整、事件状态不匹配或仍失败，停止盲目重试并保留日志。不要重下载或重生成 STRM 掩盖问题。

HOLD 不是 Person 删除批准，也不是媒体处理成功凭证；核心媒体事务和队列完成状态需分别核验。
