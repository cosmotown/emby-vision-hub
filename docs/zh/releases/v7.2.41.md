# v7.2.41 — Webhook 历史失败记录恢复与归档

修复媒体已经正常，但旧 Webhook 失败记录仍长期计入告警、只能反复点击重试的问题。

- 后续 media_process 成功，且同来源、精确媒体 ID、任务参数、Episode 集合完整覆盖及执行时间顺序均成立时，旧失败标为“已恢复”。仅凭剧名相同不能核销；证据不足仍保留失败。
- 增加管理员“确认已恢复并归档”。先检查媒体、集数、详情及播放正常，再显式确认；只改变单条 failed 的队列终态，保留原错误与确认人，不触发重放、不伪造执行成功。
- 处理中、待处理及等待重试记录不能归档；重复归档和归档后重试返回状态冲突，防止连续点击重复处理。
- 已恢复/已归档不再计入待处理失败，恢复/归档时间另行记录，进入原有30天历史保留范围；未解决的失败不会自动过期。
- 升级启动时可利用队列中已保留的成功证据核对旧失败，无需重新处理媒体。没有自动重放历史 Webhook。

## 数据与兼容边界

本版本只为 `webhook_event_queue` 添加 `resolution_json`、`resolved_at` 和一个匹配索引，并增加队列状态/API/UI及回归测试。

不修改人物、媒体、`actor_metadata`、`person_identity_map`、`person_cleanup_candidates`、保护库配置或保护快照；不执行任何 Person 删除、合并或历史人物清理。v7.2.40 的 Person HOLD 与媒体入库失败隔离保持不变。

不改变 VidHub、Infuse、官方 Emby 的虚拟库、权限、Recent、详情、图片或播放逻辑，也不改变 STRM、MoviePilot/115 或更新器业务。

不包含本地人物审计/Inventory工具、生产扫描产物、账号凭据或合成测试媒体。本次发布不自动部署 NAS。

## 升级与使用

正式镜像：`tzyzero186/emby-vision-hub:7.2.41`。

通过现有 Portainer Stack / Compose 管理器更新并重建容器，保留全部现有配置、挂载、端口及网络；确认容器内部版本为7.2.41且健康检查通过。

媒体已经正常时，不需要为了消除历史告警逐条重试：自动有覆盖证据的记录会标为已恢复；其他记录请检查完整性后使用“确认已恢复并归档”。媒体仍缺失或核心处理仍失败时，继续保留错误并排查，不要用归档掩盖真实故障。

## 验证范围

新增20项队列回归，覆盖精确ID、同名异人、Episode覆盖不全、时间顺序、状态竞态、原错误保留、权限、数据库失败及保留期。包含真实本地API的合成生命周期验证；没有用本地测试冒充生产媒体或播放器实机验收。
